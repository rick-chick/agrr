# SEO 改善レビュー観点（一般ベストプラクティス）

プロジェクト固有の実装・設定は対象外。**2025–2026 年時点**の Google 公式・業界コンセンサスに基づく、SEO 監査・改善レビュー用の観点一覧。

関連（本リポジトリ固有）: [`vitepress-rebuild-checklist.md`](vitepress-rebuild-checklist.md)

## レビューの前提

| 観点 | 内容 |
| --- | --- |
| 監査順序 | **下位レイヤーから**（クロール → インデックス → レンダリング → 体験 → 構造化 → AI 可視性）。上位だけ直しても下位が壊れていれば無効 |
| データの優先 | **フィールドデータ**（CrUX / Google Search Console）を主とし、ラボ計測は診断用 |
| 2026 年の主要シフト | INP（FID 廃止）、AI Overviews / 生成検索、**パッセージ単位の取得**、エンティティ・ブランド信頼 |
| 測定の二軸 | 従来のランキング **＋** AI 引用・要約での可視性 |

## 1. クロール・インデックス（最優先）

| # | レビュー観点 | 確認内容 |
| --- | --- | --- |
| 1.1 | robots.txt | 重要コンテンツ・CSS/JS が誤ブロックされていないか。AI クローラー（GPTBot, PerplexityBot, Google-Extended 等）の方針が意図的か |
| 1.2 | インデックス状況 | GSC で「インデックス登録済み / 未登録 / 除外」の意図と一致しているか |
| 1.3 | XML サイトマップ | 200・インデックス可能 URL のみ。正規 URL と一致。サイトマップインデックスの登録・更新 |
| 1.4 | 重複・正規化 | 自己参照 `rel=canonical`、パラメータ・www/non-www・HTTP/HTTPS・末尾スラッシュの統一 |
| 1.5 | noindex / robots meta | 薄い・重複・ステージングページが意図的に除外されているか |
| 1.6 | リダイレクト | チェーン・ループの解消。301/302 の使い分けが正しいか |
| 1.7 | 404 / 5xx | 壊れたリンク、サーバーエラー、ソフト 404 の有無 |
| 1.8 | オーファンページ | 内部リンクから到達不能な重要ページがないか |
| 1.9 | レンダリング | **初期 HTML（view-source）に本文が存在**するか。CSR のみでコンテンツが空になるページがないか |
| 1.10 | ログ解析 | クローラーの実挙動がツール推定と一致しているか |

## 2. URL・アーキテクチャ・ナビゲーション

| # | レビュー観点 | 確認内容 |
| --- | --- | --- |
| 2.1 | クリック深度 | 重要ページがホームから **≤3 クリック** で到達可能か |
| 2.2 | URL 設計 | 読みやすく、階層が論理的。不要な深さ・動的パラメータを避ける |
| 2.3 | 内部リンク | 意味あるアンカーテキスト、重要ページへのリンク集中度 |
| 2.4 | パンくず | 構造化データ（BreadcrumbList）と視覚表示の整合 |
| 2.5 | ファセット・フィルタ | 無限 URL 生成、低品質インデックスの膨張を防いでいるか |
| 2.6 | サイトマップ vs 実リンク | サイトマップに載るが内部リンクが薄いページの有無 |

## 3. ページ体験・Core Web Vitals

| 指標 | 良好基準（75 パーセンタイル） | レビュー観点 |
| --- | --- | --- |
| **LCP** | ≤ 2.5s | ヒーロー画像・フォント・TTFB・CDN・プリロード |
| **INP** | ≤ 200ms（競合は 150ms 目標） | 長タスク分割、JS 実行量、イベントリスナー、メインスレッド負荷 |
| **CLS** | < 0.1 | 画像・広告・埋め込みのサイズ予約、動的挿入の抑制 |

追加観点:

- モバイルフィールドデータを優先（モバイルファーストインデックス）
- テンプレート単位で主要 URL を計測（ランダム 1 ページだけでは不十分）
- 侵入的インタースティシャル（特にモバイル）の回避
- TTFB < 500ms を目安にサーバー応答を確認

## 4. モバイル・レスポンシブ

| # | レビュー観点 |
| --- | --- |
| 4.1 | モバイルフレンドリー（タップターゲット、横スクロール、文字サイズ） |
| 4.2 | 同一 URL でのレスポンシブ vs 別 URL（m.）の方針が一貫 |
| 4.3 | モバイルでの CWV がデスクトップより劣化していないか |

## 5. セキュリティ・技術衛生

| # | レビュー観点 |
| --- | --- |
| 5.1 | 全ページ HTTPS、混合コンテンツなし |
| 5.2 | HSTS の適用 |
| 5.3 | セキュリティヘッダー（適切な CSP 等） |
| 5.4 | 正規ドメインの統一（www / non-www / サブドメイン乱立） |

## 6. オンページ要素

| # | 要素 | レビュー観点 |
| --- | --- | --- |
| 6.1 | **title** | ページごとにユニーク。主要キーワードを前方。目安 50–60 文字。H1 と**テーマ的に整合**（Google の title 書き換え率が高い） |
| 6.2 | **meta description** | ユニーク。目安 150–160 文字。CTR 向上の価値提案・CTA |
| 6.3 | **H1** | 1 ページ 1 つ。title と重複しすぎず主題が明確 |
| 6.4 | **見出し階層** | H2–H6 の論理構造。スキップ・乱用なし |
| 6.5 | **検索意図** | 情報・比較・取引・ナビゲーション等、意図とコンテンツ形式の一致 |
| 6.6 | **画像** | alt、適切な形式（WebP 等）、サイズ最適化、lazy load の適切な使い方 |
| 6.7 | **OG / Twitter Card** | SNS 共有時の表示品質 |
| 6.8 | **robots meta** | index/noindex, follow/nofollow の意図 |

## 7. 構造化データ（Schema.org / JSON-LD）

| # | レビュー観点 |
| --- | --- |
| 7.1 | **JSON-LD** を推奨形式として採用 |
| 7.2 | 表示コンテンツとスキーマの**完全一致**（虚偽・過剰マークアップなし） |
| 7.3 | タイプ別: Article, Organization, Person, Product, FAQ, Breadcrumb, LocalBusiness 等、ページ種に応じた適用 |
| 7.4 | Rich Results Test / GSC でエラー・警告の解消 |
| 7.5 | `dateModified` 等、鮮度シグナルの正確性 |
| 7.6 | エンティティ一貫性（著者・組織・ブランドの統一表記） |

## 8. コンテンツ品質・E-E-A-T

E-E-A-T は単一スコアではなく、品質評価のフレームワーク。**Trust（信頼）が中心**。

| 次元 | レビュー観点 |
| --- | --- |
| **Experience（経験）** | 一次体験・独自データ・事例・スクリーンショット・再現可能な手順 |
| **Expertise（専門性）** | 著者の実績、資格、専門分野との一致。著者ページ・バイオの充実 |
| **Authoritativeness（権威）** | 業界での認知、権威ある外部からの言及・引用 |
| **Trustworthiness（信頼）** | 連絡先、About、プライバシー・利用規約、HTTPS、出典明示 |

追加観点:

- **People-first**: 検索順位のためだけの量産・薄いコンテンツでないか
- **Information gain**: 上位結果を要約しただけの「コモディティ」コンテンツでないか
- **鮮度**: 日付だけ変えた偽更新ではなく、実質的な更新か
- **YMYL**: 健康・金融・安全等で特に厳格な根拠・専門性が必要
- AI 生成コンテンツ: 禁止ではないが、人の監修・独自洞察がないと品質基準に届かない

## 9. コンテンツ構造・トピック設計

| # | レビュー観点 |
| --- | --- |
| 9.1 | **トピッククラスター / ピラー構造** — 関連意図を網羅 |
| 9.2 | **検索意図の多様性** — ヘッド語だけでなく関連・会話型・ロングテール |
| 9.3 | **自己完結パッセージ** — 100–300 語程度の「抜き出し可能」ブロック |
| 9.4 | **BLUF** — 各見出し直下に 30–60 語の直接回答 |
| 9.5 | 読みやすさ — 短段落、箇条書き、表、明確な見出し |
| 9.6 | 事実の一貫性 — サイト内外で矛盾する情報がないか |
| 9.7 | 統計・出典 — 一次ソースへの引用、数値の根拠 |

## 10. AI 検索・GEO / AEO（2025–2026）

従来 SEO と**共有基盤は同じ**だが、レビュー観点が増える。

| # | レビュー観点 |
| --- | --- |
| 10.1 | **取得可能性** — AI クローラーがブロックされていないか |
| 10.2 | **HTML 内の回答** — JS 実行前にパッセージが存在するか |
| 10.3 | **Query Fan-out** — 1 クエリが多数のサブクエリに分解される前提で、多様な関連意図をカバー |
| 10.4 | **引用適性** — 段落が単体で意味を持ち、曖昧表現が少ないか |
| 10.5 | **ブランド・エンティティ** — 組織名・製品名の一貫性、外部権威サイトでの言及 |
| 10.6 | **AI Overviews 適格性** — 取得・抽出・裏付けの 3 条件を満たすか |
| 10.7 | **llms.txt**（任意） — LLM 向けサイト概要の提供（必須ではない） |
| 10.8 | **引用ドリフト** — AI 引用は月次で大きく変動するため、定期モニタリングが必要 |

## 11. 国際化・多言語（該当時）

| # | レビュー観点 |
| --- | --- |
| 11.1 | `hreflang` の双方向リンク（全バリアント間） |
| 11.2 | 自己参照 hreflang の存在 |
| 11.3 | 正しい ISO 639-1 / 3166-1 コード |
| 11.4 | hreflang と canonical の矛盾なし |
| 11.5 | 言語別 URL 設計（ccTLD / サブドメイン / パス）の一貫性 |

## 12. オフページ・ブランドシグナル

| # | レビュー観点 |
| --- | --- |
| 12.1 | 質の高い被リンク（関連性・権威・自然性） |
| 12.2 | ブランド検索量・直接流入の推移 |
| 12.3 | 第三者レビュー・評価サイトでの評価 |
| 12.4 | ソーシャル・ニュース等での一貫したブランド言及 |
| 12.5 | NAP 一貫性（ローカル SEO 該当時） |

## 13. 計測・継続モニタリング

| ツール / レポート | 監視項目 |
| --- | --- |
| Google Search Console | インデックス、CWV、構造化データ、手動ペナルティ |
| CrUX / PageSpeed Insights | LCP, INP, CLS（フィールド優先） |
| アクセス解析 | 自然検索 CTR、ランディングページ、直帰・エンゲージメント |
| クロールツール | 重複、壊れリンク、リダイレクト |
| AI 可視性ツール | ChatGPT / Perplexity / AI Overviews での引用・言及 |
| ログ解析 | ボット挙動、クロール効率 |

推奨頻度:

- **週次**: GSC アラート、重大エラー
- **月次**: CWV、インデックス差分、AI 引用
- **四半期**: フルテクニカル監査（45–150 項目規模）

## 14. 優先度分類（修正の順序）

| 優先度 | 例 | 目安 |
| --- | --- | --- |
| **Critical** | 重要ページのクロール/インデックス阻害、5xx、HTTPS 障害 | 48 時間以内 |
| **High** | CWV 不合格（フィールド）、canonical 欠落、構造化データエラー | 2 週間以内 |
| **Medium** | meta 最適化、内部リンク改善、サイトマップ整理 | 30 日以内 |
| **Low** | OG 画像改善、マイナーな alt、表現の微調整 | バックログ |
